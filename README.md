# Practical Book Distiller

> 给读不完实用书的人：先看能解决什么问题，再按需回到原文深读。

面向实用型书籍的 Codex Skill。它把信息密度不均、重复较多的书，整理成按问题检索的阅读包：先浏览核心观点，再选择性阅读方法、案例和证据，并回溯到原书对应页码。

## 目标读者

这个 Skill 主要面向以下读者：

- 买了很多自我成长、管理、效率类书籍，却经常读到一半放弃；
- 时间有限，不想从头读完重复较多、信息密度不均的实用书；
- 面对一本书时，不知道哪些章节值得优先阅读；
- 只想先解决一个具体问题，例如“如何建立习惯”或“如何改善沟通”；
- 希望先看核心观点和可执行方法，再决定是否完整阅读；
- 使用 Obsidian、Codex 或其他 Markdown 知识库管理读书笔记。

## 项目目的

本项目不是把书简单压缩成一篇摘要，而是建立一条更高效的阅读路径：

1. 先判断这本书能解决哪些问题；
2. 快速浏览最值得看的核心观点；
3. 提取可以立即尝试的方法；
4. 按兴趣和实际需求选择章节深读；
5. 随时回到原书对应页码，核对上下文和证据；
6. 明确哪些内容被保留、哪些内容被暂缓阅读。

最终希望达到的效果是：不必先读完整本书，也能先获得可靠的核心认知；当某个观点真正与你有关时，再回到原文深入理解。

## 适用范围

适合个人成长、学习方法、时间管理、习惯养成、管理沟通、决策方法、商业实践等信息密度不均的实用型书籍。

不适合直接用于小说、纯文学作品、法律或医疗等高风险个性化建议，以及需要完整逐句保存的教材或研究专著。

## 开始前需要准备什么

### 书籍电子版

请先准备你依法取得使用权的 PDF 或 EPUB 文件，例如：

- 出版社或正版电子书平台购买；
- 微信读书、Kindle、Apple Books 等合法阅读服务；
- 图书馆借阅或馆藏数字资源；
- 公版、开放许可或作者明确授权的电子书；
- 你本人依法持有的 PDF/EPUB 文件。

文件格式优先级：

1. 可复制文字的 PDF；
2. EPUB；
3. 经过可靠 OCR 的扫描 PDF。

扫描版或 OCR 质量较差的 PDF 可能出现页码错误、段落顺序混乱、表格和脚注丢失等问题。请在使用前确认文件来源、版权许可和安全性。

本项目不提供、不索引未经授权的版权下载地址，也不接受将完整书籍、盗版 PDF 或 EPUB 上传到仓库。

### 保留原始文件

建议将原书放在 Obsidian Vault 中：

```text
_attachments/Books/<书名>.pdf
```

原始文件是最终证据来源。Skill 生成的笔记只保留必要的观点、方法和导航，不替代原书。

## 基本用法

将书籍文件、阅读目标和输出位置告诉 Codex：

```text
请使用 practical-book-distiller 处理这本书：

- 书名：
- 文件路径：
- 我最关心的问题：
- 希望重点关注的章节或主题：
- 输出语言：中文
- 输出位置：当前 Obsidian Vault

请优先提取核心观点、可执行方法和重要证据。
不要生成整本书的全文转写。
保留原 PDF 页码链接，并标明有意跳过的内容。
```

## 工作流程

Skill 采用 L0–L5 流程：

1. **目标与类型路由**：判断书籍类型、阅读目标和适用范围；
2. **来源保全与证据定位**：保留原始 PDF/EPUB，记录页码、章节和解析限制；
3. **快速浏览与命题台账**：扫描目录、序言、结论、章节摘要和重复术语；
4. **选择性蒸馏**：只生成有助于理解、检索或行动的概念卡、方法卡和少量案例卡；
5. **问题导航**：根据读者问题组织入口，而不是简单堆叠章节摘要；
6. **结构与语义验收**：检查链接、来源锚点、卡片字段、范围说明和方法可执行性。

## 输出结构

在 Obsidian 中，推荐使用以下结构：

```text
20_Notes/Reading/<书籍 slug>/
├── 入口.md
├── 问题导航.md
├── 结构与原文索引.md
├── 概念/
├── 方法/
└── 案例/              # 仅在确有独立迁移价值时创建

90_AI/<书籍 slug>/
└── manifest.yaml
```

三个导航页面职责不同：`入口.md` 是默认起点，`问题导航.md` 按读者问题查找，`结构与原文索引.md` 查看全书结构、原文页码和已选择/暂缓主题。

## PDF 原文回溯

对于页码稳定的 PDF，默认使用原始文件链接：

```md
[[_attachments/Books/示例书.pdf#page=202|PDF p. 202]]
```

也可以嵌入指定页：

```md
![[示例书.pdf#page=202]]
```

卡片中的原文链接应尽量指向具体页码或章节，不使用无法验证的页码和引用。

## 卡片类型

### 概念卡

记录核心结论、要解决的问题、背后的机制、作者解释、案例或证据、适用边界、应用方式和原文链接。

### 方法卡

记录方法目标、使用原则、最小执行步骤、十分钟启动动作、适用场景、失败时的单变量调整规则，以及成功阈值或验证指标。

### 案例卡

只有在案例具有独立迁移价值，或能防止核心观点被误解时才创建。

## 证据边界

Skill 会区分作者观点、作者个人经历、书中案例、书中转述的研究和已核查的独立证据。

书中提到的研究默认仍然标记为“书中转述”，不会自动升级为已验证证据。原文解析不完整、页码不确定或上下文缺失时，应降低结论强度，并提示读者回到原 PDF 检查。

## 设计原则

- 不以卡片数量代表质量；
- 不把普通摘要伪装成全书覆盖；
- 不默认保存整本书的文字镜像；
- 不删除改变结论含义的限定条件；
- 不为每一章强行创建卡片；
- 不把个人实践日志混入通用 Skill；
- 原书是证据源，蒸馏结果是导航层。

## 局限

蒸馏结果是有损压缩，不能替代完整阅读。需要完整理解论证过程、核对限定条件、确认数字或研究出处时，应回到原书。
